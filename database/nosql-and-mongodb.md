## SQL vs NoSQL: how do you choose?

Medium
{: .label .label-yellow }

**Answer**

Choose **SQL** for structured data, joins and strong transactional guarantees (payments, ledgers). Choose **NoSQL** (e.g. MongoDB) for flexible schemas, hierarchical documents or very high horizontal write scale. Many systems use both: relational for core transactions, document store for catalogs or profiles.
